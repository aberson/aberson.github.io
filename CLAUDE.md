# aberson.github.io — project instructions

## Project overview

Abraham Robison's personal **portfolio website** — a static Astro site published
free at `https://aberson.github.io` via GitHub Pages, to show my work to hiring
managers and recruiters. No backend, no database, no accounts. Content is
markdown; `git push` to `main` auto-rebuilds and redeploys. It reuses existing
material: curated bio from `../aberson-profile/README.md` and case-study source
from `../Career/`. Work-section card/table content is generated by the
**dev-observatory** control plane (`src/data/portfolio.json`); brand tokens are
self-contained in `brand/`. Full plan: [`plan.md`](plan.md); Work-section refresh
feature plan: [`documentation/portfolio-refresh-plan.md`](documentation/portfolio-refresh-plan.md).

## Stack

| Layer | Tool |
|---|---|
| Generator | Astro (TypeScript) + Content Collections |
| Styling | Tailwind v4 (`@tailwindcss/vite`) + vendored brand tokens |
| Content | Work section from `src/data/portfolio.json` (dev-observatory export, Zod §5d gate); flagship case studies as Markdown in `src/content/projects/` |
| Hosting | GitHub Pages — user site, repo `aberson.github.io` |
| Deploy | GitHub Actions (hand-written build gates → `upload-pages-artifact` → `deploy-pages`) |
| Deps | Dependabot (npm + github-actions, weekly) |

## Key commands

```powershell
npm install            # one-time
npm run dev            # http://localhost:4321, hot reload
npm run check          # astro check — validate content + types
npm run build          # production build to dist/
npm run preview        # serve the built dist/ locally
```

Publish = commit + push to `main` (the Action deploys). Add a project = add a
`.md` file under `src/content/projects/` and push. See `CONTENT.md`.

## Architecture summary

Static, fully pre-rendered. A single-page **hub** (`/`) — header, hero, the
five-group **Work section**, "how it all fits together", about, resume, contact,
footer — plus **case-study subpages** (`/work/<slug>`) generated only for
`featured: true` projects. The Work section (Flagship cards, Utility + Third-party
tables, Fun + Professional grids) is generated from `src/data/portfolio.json` — an
export from the **dev-observatory** control plane (the single place project
descriptions are edited) — read through `src/data/portfolio.ts`, which Zod-validates
it against the §5d contract and **fails the build loudly** on drift (plus a
group-count pin). The content collection now supplies only the flagship case-study
BODIES + routes. Visual identity is the site's OWN vendored brand tokens (`brand/`
source, re-vendored into `src/assets/` by `scripts/sync-brand.ps1` — no cross-repo
dependency, not the starter theme); the palette is **cream/gold with auto light/dark**
(`prefers-color-scheme`, no forced theme). GitHub + LinkedIn links are persistent in
header and footer. Built domain-ready (`base: '/'`) so a later custom domain is a
`site` change + `CNAME` file with no rebuild.

## Environment requirements

- Windows 11 + PowerShell. **Node 22.12+** and npm for Astro (Astro 7 minimum; dev + CI run Node 24).
- A GitHub account (`aberson`); the repo must be named `aberson.github.io`
  (user-site requirement) and public.
- No API keys or secrets — a static site needs none; never commit any.
- Identity (LinkedIn, contact email, value prop) is resolved in `src/consts.ts`
  (no `TODO:` remains — a CI no-`TODO` gate now enforces this). `public/resume.pdf`
  is the real export (source: career-ops `output/cv-abraham-robison-general-*.pdf`);
  to update it, regenerate in career-ops, re-copy, bump `LAST_UPDATED`, and push.
